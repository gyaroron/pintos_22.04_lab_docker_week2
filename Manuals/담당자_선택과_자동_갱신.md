# 담당자 선택과 자동 갱신

팀 저장소: [PintOS Week2](https://github.com/gyaroron/pintos_22.04_lab_docker_week2) · [칸반보드](https://github.com/users/gyaroron/projects/10)

2026-10-21 추가 정책: **사람이 카드를 `Todo`로 옮기면 실제 Assignees를 모두 해제하고, 본문·상위 표의 주 담당자도 공란으로 만든다. `In Progress`·`In Review`·`Done`으로 옮기면 최근 이동자 한 명으로 기존 Assignees를 교체한다.** 리뷰어는 사용자가 따로 선택한다.

기본 Project 자동화는 PR #161 병합·설정·활성화를 마쳤다. **이 문서의 `Todo → 담당 해제` 변경은 별도 추가 PR의 승인과 `main` 병합 후 적용된다.** 기존 자동화가 켜져 있거나 문서가 있다는 것만으로 Todo 해제도 적용된 것으로 판단하지 않는다. [설정·검증·명령어](Project_상태와_담당자_자동화.md)를 따른다.

## 작업을 맡는 방법

1. 상위 Issue의 native Sub-issue 목록에서 실제 맡을 작업을 고른다.
2. 해당 하위 카드의 요구사항·의존 작업·현재 담당자와 팀원의 진행 상황을 확인한다.
3. **본인 계정으로 로그인한 상태에서** 카드를 `Todo`, `In Progress`, `In Review`, `Done` 중 실제 상황에 맞는 열로 옮긴다.
4. 카드의 Status는 이동 즉시 바뀐다. 추가 자동화는 약 5분 간격으로 확인하며 GitHub 예약 실행 사정에 따라 더 늦어질 수 있다.
5. 실행 완료 후 `Todo`이면 **실제 Assignees가 비어 있고** 본문·상위 표의 `주 담당자`도 공란인지 확인한다. 나머지 세 상태이면 **Assignees가 이동한 본인 한 명인지**, 본문·상위 표도 일치하는지 확인한다.

예를 들어 A가 맡던 카드를 B가 `In Review`로 옮기면, 자동화 완료 후 실제 Assignees와 주 담당자 표시는 B 한 명이 된다. A의 배정은 유지하지 않는다. B가 그 카드를 `Todo`로 돌리면 B에게 배정하지 않고 담당을 모두 해제한다. 나머지 세 상태로 다른 사람의 카드를 정리하려고 옮기면 본인에게 담당이 바뀌므로, 본인이 맡는 의미의 이동인지 먼저 확인한다.

같은 상위 Issue 아래 서로 다른 Sub-issue를 나누어 맡는다. 한 자식 카드의 이동으로 형제나 부모의 Assignees까지 바뀌지는 않는다. 부모 카드를 사람이 직접 이동해도 그 부모에 같은 규칙을 적용한다. `Todo`는 부모 담당 해제, 나머지 세 상태는 부모 담당을 최근 이동자 한 명으로 교체한다. **카드를 이동해도 리뷰 요청을 보내거나 리뷰어를 지정하지 않는다.** PR에는 작성자를 제외한 다른 팀원 최소 1명의 승인이 필요하다.

## Assignees를 직접 선택·해제할 수도 있다

오른쪽 **Assignees**에서 직접 지정·해제한 값은 기존 표시 동기화가 본문과 상위 표에 반영한다. 모두 해제하면 표시도 공란이 된다. 여러 명을 직접 지정하면 현재 명단을 모두 표시하지만, 이후 새 수동 카드 이동이 있으면 **Todo는 모두 해제하고, 나머지 세 상태는 최근 이동자 한 명으로 교체한다.**

본문의 `주 담당자`에 아이디만 적어서는 실제 GitHub 담당자가 바뀌지 않는다. 본문을 잘못 편집했다면 **Actions → Sync issue role display → Run workflow**로 실제 Assignees에 표시를 맞춘다.

## 자동 이동과 도입 전 이력

- GitHub의 기본 자동화와 Bot이 카드를 옮긴 것은 새 담당 배정으로 처리하지 않는다. PR 작성자나 merge 버튼을 누른 사람을 추측해 담당자로 정하지 않는다.
- 도입 시각 이전의 수동 이동은 재적용하지 않는다. 아직 새로운 사람 이동이 없는 카드는 기존 Assignees를 유지한다. 추가 PR 배포 시 도입 이후의 최신 수동 이동이 `Todo`이고 현재도 `Todo`인 카드에 구정책으로 남은 배정을 한 번 해제한다. 도입 이전·Bot 이동은 이 정리에서 제외한다.
- 이 자동화가 직접 수행한 부모 카드의 `Done` 변경도 담당 배정에서 제외한다. 부모의 담당자를 토큰 소유자로 바꾸지 않는다.
- 다른 프로그램이 사람 계정의 자격증명으로 Status를 변경하면 GitHub가 일반 User 이벤트로 기록할 수 있다. 이 경우 UI에서 직접 이동한 것과 API에서 변경한 것을 이벤트만으로 완전히 구분할 수 없다.
- 읽을 수 없는 이벤트·잘못된 숨김 체크포인트·배정할 수 없는 계정이 발견되면 해당 변경을 중단하고 실행 로그에 오류를 남긴다. 더 오래된 사람에게 대신 배정하지 않는다.

## 모든 자식이 완료되었을 때

같은 저장소·같은 Project에 있는 native 자식 카드가 모두 `Done`이면 추가 자동화가 **상위 Issue를 Closed로 닫고 부모 카드도 Done으로 정리한다.** 자식이 0개이거나 누락·보관된 카드가 있으면 자동 완료하지 않는다. 중첩 자식이 있으면 그 아래까지 완료 조건을 확인한다.

하위 카드를 수동으로 `Done`에 놓는 것만으로 그 하위 Issue가 자동 종료되지는 않는다. 보통 PR 본문의 `Closes #하위번호`와 기본 브랜치 병합이 하위 Issue를 닫는다. 테스트 통과·승인·병합과 카드 위치는 구분해서 확인한다.

되돌림으로 이미 닫힌 부모를 자동 재개방하지 않는다. 자식이 모두 `Done`인 부모 카드를 다시 미완료 열로 옮기면 다음 실행에서 `Done`으로 복원될 수 있다. 재작업은 실제 미완료 자식과 부모의 재개방 여부를 함께 검토한다.

## 상태 확인

**Actions → Sync project status and ownership**에서 최근 실행의 planned/applied 수와 오류를 확인한다. 예약 실행이 비활성화되었거나 secret이 없으면 [설정 매뉴얼](Project_상태와_담당자_자동화.md)에 따라 해결한다. 최신 이벤트 체크포인트는 Issue 본문의 숨김 HTML 주석에 저장한다. 이전 담당자 목록을 별도 이력으로 저장하지 않지만 GitHub 자체의 Issue 활동 이력은 남을 수 있다.
